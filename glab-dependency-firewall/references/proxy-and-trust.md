# Dependency Firewall outbound proxy and trust selection

Use this reference when a wrapped manager needs corporate egress or custom CA trust. Proxy credentials and certificate passwords are sensitive; inspect only approved configuration and report setting names or fixed diagnostics, not values. These rules do not authorize package execution, installation, publishing, or trust-store changes.

| Manager | Outbound proxy selection and boundaries |
| --- | --- |
| npm/pnpm | Manager environment and, for npm, user/global npmrc precede general proxy fallback. pnpm configuration files are not read; pnpm uses only the supported `npm_config_*` environment settings. npm selects `https-proxy`, then `proxy`, then `HTTPS_PROXY`; npm/pnpm prefer HTTPS proxy routing for HTTP too. npm `noproxy` combines with `NO_PROXY`. Project configuration is not a source of upstream proxy settings. |
| Yarn | Classic reads supported user/global `.yarnrc` and npm configuration; Berry reads supported user configuration and its own proxy environment. Berry uses `YARN_HTTPS_PROXY`, then `httpsProxy` in `~/.yarnrc.yml`; Classic selects `https-proxy`, then `proxy` through Yarn and npm layers. Neither applies `NO_PROXY` to manager-specific proxy settings. |
| pip/pipenv | For pip on glab v1.132.0+, the last nonempty `--proxy` precedes `PIP_PROXY`, which precedes applicable command-section and global configuration. File precedence and `PIP_CONFIG_FILE`/isolated mode matter. pipenv does not select a pip command section. A nonempty manager-specific proxy ignores general HTTPS proxy and `NO_PROXY`. An empty pip `--proxy` clears pip-specific selection and leaves the default transport environment fallback; it does not force direct routing. |
| Cargo | `CARGO_HTTP_PROXY`, then Cargo-home config, then supported user/system Git `http.proxy`; empty means direct. `NO_PROXY` applies. Project `.cargo` files, Git includes, and `--config` are not read for this selection. |
| Maven | Active user settings proxies, then global entries with unused IDs; for HTTPS destinations, first matching HTTPS proxy, then HTTP. `nonProxyHosts` controls exclusions. Maven reaches a configured manager-specific proxy over plain HTTP. Maven's own selector ignores `HTTPS_PROXY`, but if no manager-specific proxy is selected, glab's outbound transport retains normal `HTTPS_PROXY`/`HTTP_PROXY` and `NO_PROXY` fallback. Project settings and `.mvn/maven.config` are excluded from upstream proxy discovery; encrypted proxy credentials are unsupported. |
| Gradle | Command-line `-D` properties, then `systemProp.*` in user-home and installation `gradle.properties`. Empty `https.proxyHost` means direct. JVM `http.nonProxyHosts` applies to HTTPS too. The manager-specific selector ignores `HTTPS_PROXY` and project properties; when `https.proxyHost` is absent, glab's outbound transport retains normal `HTTPS_PROXY`/`HTTP_PROXY` and `NO_PROXY` fallback. This absence is distinct from an explicitly empty host, which selects direct routing. |

Malformed or unreadable configuration selected for parsing can fail the run; parser diagnostics avoid echoing file contents. Skipped project files do not grant permission to move untrusted proxy configuration into a trusted user/global location.

Registry connections add `ca_cert`, supported CA-bundle environment files (`SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `PIP_CERT`, `TWINE_CERT`, `NODE_EXTRA_CA_CERTS`, `npm_config_cafile`/`NPM_CONFIG_CAFILE`, `YARN_CAFILE`, `YARN_HTTPS_CA_FILE_PATH`, `YARN_CA_FILE_PATH` (these npm/Yarn names case-insensitively in glab v1.132.0+), `BUNDLE_SSL_CA_CERT`, `CARGO_HTTP_CAINFO`), and applicable JVM anchors to system roots. Missing/unusable bundle files may be skipped with diagnostics; do not infer trust from a configured path alone.

Maven and Gradle registry connections can import trusted-certificate-only PKCS#12 truststores. JKS and JCEKS bytes are unsupported, even when the configured store type names them. A configured unsupported store is skipped with a warning; unsupported JDK-default JKS stores can be skipped without a warning. Do not infer those anchors are available to registry connections. Preserve the generated inspection truststore: later JVM options or command-line truststore overrides can replace it, leaving the manager unable to trust the local proxy; glab warns about detected overrides. Review the effective JVM settings without exposing passwords; do not turn off certificate verification.

Configured `client_cert`/`client_key` (including supported PKCS#12/password handling) can authenticate to an HTTPS outbound proxy. The certificate is presented to that proxy only, not broadcast to registries inside its tunnel. Approve the actual proxy destination and retain CA validation. This is separate from the package-manager's trust of the local inspection proxy.

For Go, the internal HTTP transport receives added roots. The Go subprocess uses a temporary CA file only when it preserves system trust; macOS/Windows and an `SSL_CERT_DIR`-only configuration keep the subprocess's original trust. These exceptions can affect direct module/git fetches. The job proxy's system-trust installation is a separate, broader operation.
